# Чат LAST FREQUENCY между компьютерами

Один пользователь создаёт чат прямо в плеере. Пока его плеер работает, он хранит и передаёт сообщения остальным участникам. Отдельный постоянно работающий сервер не обязателен.

## Создать чат

1. Открой «Чаты», введи ник и включи чат.
2. Выбери «Создать чат на этом компьютере». По умолчанию используется TCP-порт `8786`.
3. Нажми «Применить». Если код не заполнен, плеер создаст случайный код доступа.
4. Передай другу адрес компьютера, порт и код. Друг выбирает «Подключиться к другу» и вводит эти данные.

В одной сети подойдёт адрес, который показывает плеер, например `http://192.168.1.20:8786`. Это пример адреса, а не готовый доступный сервис.

Для разных сетей есть два варианта:

- общий VPN с доступом между устройствами: друг указывает VPN-адрес компьютера-хоста;
- проброс TCP-порта на роутере и разрешение входящего подключения в брандмауэре: друг указывает внешний адрес и внешний порт.

Если провайдер использует CGNAT, обычного проброса порта на домашнем роутере недостаточно. Используй VPN с доступом между участниками либо компьютер с доступным публичным адресом. Плеер не настраивает роутер, VPN или брандмауэр и не выполняет автоматический NAT traversal. Публичный IP не определяется через внешние сервисы.

Все комнаты в одном хосте общие для пользователей с кодом. Это групповой чат, а не приватная личная переписка. Ники служат именами для отображения, не подтверждают личность. Не передавай код посторонним.

## Нагрузка и хранение

- Чат по умолчанию выключен. В этом состоянии нет сервера, опроса сообщений, сетевого обнаружения или фонового таймера чата.
- При закрытии окна «Чаты» прекращается опрос сообщений. Если ты создал чат, хост продолжает работать для друзей.
- Выключение галочки «Включить чат» закрывает сервер и его порт. Участники теряют связь, пока хост не включит чат снова.
- В открытом окне сообщения запрашиваются раз в 5 секунд. В скрытом окне опрос останавливается; при ошибках интервал увеличивается.
- На компьютере-хосте переписка хранится в `chat-data/chat.sqlite3`. Сохраняются последние 20 000 сообщений. У каждого клиента в памяти ограничено 300 видимых сообщений.
- Файлы музыки, пути к ним и обложки автоматически не загружаются. Рекомендации содержат метаданные и публичные ссылки на музыкальные площадки. В плейлисте можно передать до 100 таких треков.
- Сервер принимает сообщения до 2000 символов, ограничивает число сообщений и одновременных подключений. История видна всем участникам соответствующей комнаты.

Прямой `http://` не шифрует сообщения и код доступа при передаче. Для связи через интернет используй защищённый VPN либо HTTPS перед хостом. Сессии действуют семь дней, хост хранит только хеши сессионных токенов.

## Необязательный отдельный хост

Тот же сервер можно запускать отдельно на компьютере или VPS с Python 3.10+:

```powershell
$env:CHAT_SERVER_KEY = "случайный-длинный-код-доступа"
python chat_server.py --host 127.0.0.1 --port 8786 --database chat-data/chat.sqlite3
```

Клиенты вводят этот код. Ключ хранится в окружении процесса; он не включается в исходники. Пример переменных: [chat-server.env.example](chat-server.env.example).

Для HTTPS можно поставить Caddy перед сервером. Ниже `chat.example.com` — заменяемый пример домена, который должен принадлежать владельцу хоста:

```caddy
chat.example.com {
    request_body {
        max_size 64KB
    }
    reverse_proxy 127.0.0.1:8786
}
```

Постоянный хост и HTTPS не разворачиваются автоматически. Плеер не зависит от стороннего общего сервера.

## API для мобильного и настольного клиента

Все ответы JSON. Внешний адрес указывает корень хоста, без дополнительных путей.

| Запрос | Данные | Ответ |
| --- | --- | --- |
| `POST /api/chat/session` | `{nickname, client_id}`; `Authorization: Bearer <код>` | `{token, expires_at, nickname, rooms}` |
| `GET /api/chat/rooms` | сессионный bearer | `{rooms:[{id,name}]}` |
| `POST /api/chat/rooms` | `{name}` | `{room:{id,name}}` |
| `GET /api/chat/messages?room=general&after=0&limit=100` | сессионный bearer | `{items:[message],cursor}` |
| `POST /api/chat/messages` | `{room,text,kind,attachment,nonce}` | `{message}` |

`client_id` и `nonce` — случайные идентификаторы из 16–80 латинских букв, цифр, `_` и `-`; UUID подходит. Одинаковый `nonce` от одного клиента не создаёт дубликат. Для всех запросов после создания сессии используется `Authorization: Bearer <token>`.

`message` содержит `id`, `room`, `nickname`, `kind`, `text`, `attachment` и `created_at` (Unix seconds). Вложения:

- `kind: "text"`: `attachment: null`;
- `kind: "track"`: `{title,artist,url,provider}`;
- `kind: "playlist"`: `{title,url,tracks:[{title,artist,url,provider}]}`. Достаточно ссылки плейлиста или списка треков.

Ссылки во вложениях — только HTTPS YouTube, SoundCloud, Spotify, Apple Music и Яндекс Музыки. Ошибки имеют вид `{error:"…"}` и HTTP-код `400`, `401`, `403`, `413`, `415`, `429` или `500`.

Настольный плеер проксирует запросы через свой локальный API: сессионный токен передаётся в `X-Chat-Session`; локальный токен плеера не передаётся собеседникам. Мобильный клиент может обращаться к адресу хоста напрямую.
